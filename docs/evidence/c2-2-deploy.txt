What happened:
- Revision 1 (helm install --wait --timeout 25m) failed after 603 s with
  "Deployment/robot-shop/ratings ... shipping not ready ... Progress deadline
  exceeded". Kubernetes gives each Deployment 600 s by default.
- Cause: on first start MySQL imports 10-dump.sql.gz (the shipping city list)
  into a temporary server that listens on no TCP port, so ratings and shipping
  got "Connection refused" until the import finished. MySQL has no readiness
  probe in the upstream chart, so it looked ready during the import. Its
  0.2 CPU limit made the import slow: cgroup cpu.stat showed about 36 s of CPU
  used and about 171 s throttled at 10:57 UTC.
- MySQL logged "ready for connections ... port: 3306" at 10:58:47 UTC. ratings
  and shipping became ready by 11:00:50 UTC with 0 restarts and no changes.
- Revision 2 (helm upgrade --reuse-values, same chart and values) recorded the
  healthy state. No pod was restarted or replaced.
