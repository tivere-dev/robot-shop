## Finding, NOT fixed: load-gen is OOMKilled repeatedly
load-c4ffbbd6d-nqvmc started=2026-10-26T16:31:11Z restarts=42 last=OOMKilled/137 limit=
Cause: load-gen (Locust) requests URLs that contain unique values, e.g.
/api/cart/add/<uniqueid>/<sku>/1 and /api/shipping/calc/<city uuid>, without
Locust's name= grouping (load-gen/robot-shop.py). Locust keeps statistics per
distinct URL, so its memory grows until the 200Mi limit kills it. Between kills
Kubernetes backs off before restarting (CrashLoopBackOff), so traffic is
intermittent.

## load-gen fix (robot-shop revision 7)
Captured: 2026-10-26 20:29 UTC
Change: the load container runs ./entrypoint.sh in a shell loop with RUN_TIME=3m, so each Locust
run starts with empty per-URL statistics and the container never exits (no restart back-off).
Memory limit 200Mi -> 384Mi.
